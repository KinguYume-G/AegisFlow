# Design Note — AF-204 Implement local Docker sandbox baseline

> 状态：**Draft v2**，等待人工最终 Review。依赖 AF-102（已合并）。Codex 在获得批准前不得实现。v2 行为以共享契约 §0A 为准。
> 前提文档：`docs/design-notes/M2-SHARED-CONTRACTS.md`（第 7、13 节）。GitHub #23。ADR-0009、`09_SECURITY_BASELINE.md`。

## Draft v2 implementation contract

- 禁止把通用 `docker-socket-proxy` 当作权限边界，也禁止 Core 或沙箱容器直接持有 Docker socket。
- `SandboxBroker` 是窄协议适配边界：只接受结构化请求并在服务端重建 Docker 参数，拒绝 privileged、devices、任意 mount、额外 capabilities、网络和未锁 digest 的镜像。
- workspace 由调用方创建和清理；runner 只清理自己创建的容器。返回结果时 workspace 必须仍存在，供 AF-205 生成 diff。
- `InMemorySandboxRunner` 只返回注入的确定性结果，绝不在宿主机执行请求中的命令。

## Problem

Executor（AF-205）需要一个非 root、资源受限、网络默认关闭、执行后彻底清理的临时执行环境来运行测试；仓库目前没有任何沙箱能力，Core 容器本身也不应该获得 Docker Socket 访问权限。

## Objective

按 Issue #23 AC（"禁止 Docker socket；网络可控；超时和清理测试通过"），实现：

1. `SandboxRunner` 协议 + `DockerSandboxRunner`（真实实现）+ `InMemorySandboxRunner`（测试 fake）；
2. `compose.yaml` 新增窄协议 `sandbox-broker`，Core 仅调用其结构化 API，Core 与执行容器均不挂载 Docker socket；
3. non-root、read-only FS、resource limit、timeout、network=none、cleanup 全部落地并有负向测试。

## Non-Goals

- 不接入 Executor 业务逻辑（AF-205 范围，本 Issue 只交付通用 `SandboxRunner`）。
- 不实现网络 allowlist 分支（M2 固定 `--network=none`，见 SHARED-CONTRACTS §7.1）。
- 不实现 M5 的 k3s Ephemeral Job（ADR-0009 两阶段的第二阶段）。
- 不引入任何真实模型/GitHub 调用。

## Affected Modules

- 新增 `gateway/sandbox/__init__.py`、`runner.py`（协议 + Schema + `InMemorySandboxRunner`）、`docker_runner.py`（`DockerSandboxRunner`）。
- 修改 `compose.yaml`：新增 `sandbox-broker`；Core 新增 `SANDBOX_BROKER_URL` 与内部网络依赖。
- 修改 `settings.py`：新增 `sandbox_broker_url` 与 sandbox 默认/硬上限资源配置。
- 新增 `tests/gateway/sandbox/`。
- 修改 `docs/21_TRACEABILITY_MATRIX.md`。

## Proposed Flow

### Schema（`gateway/sandbox/runner.py`）

```text
class SandboxRequest(BaseModel):
    model_config = ConfigDict(extra="forbid", frozen=True)
    schema_version: Literal[1] = 1
    workspace_source: Path
    test_profile: TestProfile
    timeout_seconds: PositiveInt = 600
    memory_limit_mb: PositiveInt = 1024
    cpu_limit: PositiveFloat = 1.0
    pids_limit: PositiveInt = 256

class SandboxResult(BaseModel):
    model_config = ConfigDict(extra="forbid", frozen=True)
    schema_version: Literal[1] = 1
    status: Literal["completed", "timeout", "resource_exceeded", "internal_error"]
    exit_code: int | None
    stdout: str
    stderr: str
    duration_ms: NonNegativeFloat
    workspace_output: Path

class SandboxRunner(Protocol):
    def run(self, request: SandboxRequest) -> SandboxResult: ...
```

`stdout`/`stderr` 在构造 `SandboxResult` 前截断到 64KB（超出部分追加 `"[TRUNCATED]"`，与 AF-109 `redact()` 的截断风格一致）。

### `DockerSandboxRunner`（`docker_runner.py`）

```text
class DockerSandboxRunner:
    def __init__(self, docker_proxy_url: str): ...

    def run(self, request: SandboxRequest) -> SandboxResult:
        temp_output_dir = _create_temp_workspace_copy(request.workspace_source)
        try:
            container = self._create_container(request, temp_output_dir)
            try:
                exit_code = self._wait_with_timeout(container, request.timeout_seconds)
                stdout, stderr = self._collect_logs(container)
                status = "completed" if exit_code is not None else "timeout"
                return SandboxResult(status=status, exit_code=exit_code, stdout=stdout, stderr=stderr,
                                      duration_ms=..., workspace_output=temp_output_dir)
            finally:
                self._stop_and_remove(container)   # 无论成功/失败/超时都执行
        except _ResourceExceededSignal:
            return SandboxResult(status="resource_exceeded", ...)
        except Exception:
            return SandboxResult(status="internal_error", ...)
        # runner finally 只清理 broker-owned container；workspace 由调用方在 diff 后清理
```

容器创建参数固定：`--read-only`、`--tmpfs /tmp:size=<bounded>`、`--network=none`、`--user <non-root uid:gid>`、`--memory`、`--cpus`、`--pids-limit`、挂载 `workspace_source` 副本到 `/workspace`（读写，因为 Executor 需要在其中写入修改后的文件）。**永不**挂载 `/var/run/docker.sock` 或任何宿主路径到容器（除 `/workspace` 副本外）。所有 Docker Engine API 调用经由 `docker_proxy_url`（HTTP），不直连 Socket。

### `compose.yaml` 新增 Sandbox Broker（示意，Codex 实现时锁定镜像摘要）

```text
sandbox-broker:
  image: <AegisFlow-owned broker image pinned by digest>
  # 对 Core 只暴露结构化 SandboxRequest API；broker 在服务端重建并验证全部 Docker 参数。
  volumes:
    - /var/run/docker.sock:/var/run/docker.sock:ro
  networks:
    - sandbox-internal

core:
  networks:
    - default
    - sandbox-internal
  environment:
    SANDBOX_BROKER_URL: http://sandbox-broker:8081
```

### 清理保证

```text
finally:
    try:
        _remove_container(container_id)   # 即使已经因超时被 stop，也尝试 remove
    finally:
        _remove_temp_directory(temp_output_dir_or_workspace_copy)
```

两个清理动作互相独立包裹（一个失败不阻止另一个执行），并各自记录失败日志（不吞异常但也不让清理失败掩盖原始执行结果）。

## State Ownership / External Side Effects / Idempotency

- **State Ownership**：无持久化状态；调用方持有 workspace，runner 返回后完成 diff，再由调用方清理。
- **External Side Effects**：创建/销毁 Docker 容器（本地/CI 环境内，无跨租户影响）。
- **Idempotency**：`SandboxRunner.run()` 本身不设计为幂等（每次调用都是一次全新执行，重复调用产生新的容器实例）；Idempotency 由更上层（AF-209，针对 Draft PR 创建等真正外部写副作用）处理，沙箱执行本身允许安全重试。

## Failure Modes

| 场景 | 预期行为 |
|---|---|
| 命令执行超过 `timeout_seconds` | `status="timeout"`，容器被 `stop`+`remove` |
| 命令触发内存/PID 超限被内核杀死 | `status="resource_exceeded"` |
| Docker 代理不可达/内部错误 | `status="internal_error"`，异常类型记录在 `stderr` 摘要中（不含代理内部凭据） |
| 调用方 workspace 清理失败 | 记录安全/运维告警；不得复用该目录或泄露内容 |
| `command` 为空列表 | 构造 `SandboxRequest` 时即被 Pydantic 拒绝（`min_length=1`） |

## Security Impact

Risk Level L2。Sandbox Broker 的服务端参数验证是核心安全边界；测试必须证明客户端无法请求 privileged、devices、任意 mount、网络、额外 capability 或未锁定镜像。
