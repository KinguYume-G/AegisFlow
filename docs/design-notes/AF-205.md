# Design Note — AF-205 Implement Executor Agent contract

> 状态：**Draft v2**，等待人工最终 Review。依赖 AF-107（已合并）、AF-204（Draft，先于本 Issue 批准）。Codex 在获得批准前不得实现。v2 行为以共享契约 §0A 为准。
> 前提文档：`docs/design-notes/M2-SHARED-CONTRACTS.md`（第 8.1–8.3、12、13 节）。GitHub #24。

## Draft v2 implementation contract

- Executor 接收结构化 `TestProfile` 与经 Policy Gate 允许的 capability，不接受任意 shell command。
- 修改集使用规范化 POSIX 相对路径，并限制文件数量、单文件字节数、总内容和 patch 字节数；绝对路径、`..`、symlink escape 一律拒绝。
- 测试计数只从结构化报告解析；缺失时使用 `Measurement(status="not_available")`。
- 确定性测试必须使用两个全新的相同 workspace 副本；调用方在 diff 生成后于 `finally` 清理。

## Problem

已批准的 Plan 需要被转化为真实的代码修改与测试结果，且必须在沙箱内完成、只调用允许的工具、产出结构化 Patch/Test/Evidence，失败必须结构化而非裸异常。

## Objective

按 Issue #24 AC（"只调用允许工具；产生 Patch/Test/Evidence；失败结构化"），实现 `ExecutorAgent.execute(plan, workspace_source, sandbox_runner) -> ExecutionResult`，四阶段流程（Fetch/Apply/Execute/Diff）中 Apply 阶段确定性、Execute 阶段委托 AF-204 的 `SandboxRunner`。

## Non-Goals

- 不直接调用 GitHub 写 API（Draft PR 创建是 AF-208 职责）。
- 不直接持有 GitHub 凭据（Fetch 阶段的仓库读取由图节点通过 AF-202 完成，Executor 类本身只接收已经 fetch 好的 `workspace_source`）。
- 不引入真实 LLM/Model Provider（M2 仍是确定性 Reasoner，见 SHARED-CONTRACTS §0）。
- 不写 Run/Step 持久化（图节点职责，见 SHARED-CONTRACTS §4.2）。
- 不做 Policy Gate 校验（Executor 假定收到的 Plan 已经过 Policy Gate `allow`，不重复校验——重复校验属于职责越界，且违反"确定性 Policy 只有一个权威判断点"的原则）。

## Affected Modules

- 新增 `packs/delivery/contracts/execution_result.py`（`TestOutcome`/`ExecutionResult`）。
- 新增 `packs/delivery/executor/__init__.py`、`ports.py`（`PatchReasoner` 协议）、`fakes.py`（`DeterministicPatchReasoner`）、`agent.py`（`ExecutorAgent`、`ExecutorNodeError`）。
- 新增 `tests/packs/delivery/executor/`。
- 修改 `runtime/tracing.py`：`StepTraceRecord.agent` 的 `Literal` 追加 `"executor"`（**只追加这一个字面量，不改动文件其余内容**，见 SHARED-CONTRACTS §1）。
- 修改 `docs/21_TRACEABILITY_MATRIX.md`。

## Proposed Flow

### `ExecutionResult`（`packs/delivery/contracts/execution_result.py`）

```text
class TestOutcome(BaseModel):
    model_config = ConfigDict(extra="forbid", frozen=True)
    schema_version: Literal[1] = 1
    status: Literal["passed", "failed", "timeout", "error"]
    passed_count: NonNegativeInt
    failed_count: NonNegativeInt
    output_excerpt: str   # 有界截断，≤ 8000 字符

class ExecutionResult(BaseModel):
    model_config = ConfigDict(extra="forbid", frozen=True)
    schema_version: Literal[1] = 1
    status: Literal["completed", "failed"]
    patch: str
    changed_files: list[str]
    test_outcome: TestOutcome
    reasoner_id: str

    @field_validator("changed_files")
    @classmethod
    def changed_files_must_be_unique(cls, value: list[str]) -> list[str]:
        if len(value) != len(set(value)):
            raise ValueError("changed_files must not contain duplicates")
        return value
```

### `PatchReasoner` 端口与确定性实现

```text
class PatchReasoner(Protocol):
    def generate_patch(self, plan: Plan, workspace_files: Mapping[str, str]) -> Mapping[str, str]:
        """返回 {file_path: new_content}，只包含被修改的文件；不修改的文件不出现在返回值中。"""

class DeterministicPatchReasoner:
    """测试/Fixture 用：按预置的 (plan 摘要 → 修改映射) 表返回固定结果，不做任何启发式代码生成。"""
    def __init__(self, fixed_responses: Mapping[str, Mapping[str, str]]): ...
    def generate_patch(self, plan: Plan, workspace_files: Mapping[str, str]) -> Mapping[str, str]: ...
```

真实（未来 M3+ 接入 LiteLLM 后）实现不在本 Issue 范围内。

### `ExecutorAgent`（`packs/delivery/executor/agent.py`）

```text
class ExecutorNodeError(RuntimeError):
    def __init__(self, stage: Literal["apply", "sandbox", "diff"], cause_type: str): ...

class ExecutorAgent:
    def __init__(self, reasoner: PatchReasoner): ...

    def execute(
        self, plan: Plan, workspace_source: Path, sandbox_runner: SandboxRunner,
        test_profile: TestProfile,
    ) -> ExecutionResult:
        try:
            original_files = _read_workspace_files(workspace_source)
        except Exception as exc:
            raise ExecutorNodeError("apply", type(exc).__name__) from None

        try:
            modifications = self._reasoner.generate_patch(plan, original_files)
            _apply_modifications(workspace_source, modifications)
        except Exception as exc:
            raise ExecutorNodeError("apply", type(exc).__name__) from None

        try:
            sandbox_result = sandbox_runner.run(SandboxRequest(
                workspace_source=workspace_source, test_profile=test_profile,
            ))
        except Exception as exc:
            raise ExecutorNodeError("sandbox", type(exc).__name__) from None

        try:
            patch_text, changed_files = _diff_workspaces(original_files, sandbox_result.workspace_output)
        except Exception as exc:
            raise ExecutorNodeError("diff", type(exc).__name__) from None

        test_outcome = _map_sandbox_result_to_test_outcome(sandbox_result)
        status = "completed" if test_outcome.status == "passed" else "failed"
        return ExecutionResult(
            status=status, patch=patch_text, changed_files=changed_files,
            test_outcome=test_outcome, reasoner_id=type(self._reasoner).__name__,
        )
```

`_map_sandbox_result_to_test_outcome` 把 `SandboxResult.status`（`completed`/`timeout`/`resource_exceeded`/`internal_error`）与 `exit_code` 映射为 `TestOutcome.status`（`passed`/`failed`/`timeout`/`error`）——两套 Literal 故意不同名，因为语义层次不同（沙箱执行是否完成 vs 测试本身是否通过）。

## State Ownership / External Side Effects / Idempotency

- **State Ownership**：无（`ExecutorAgent` 本身无状态；Run/Step 持久化由图节点负责）。
- **External Side Effects**：委托 `SandboxRunner`（AF-204）创建/销毁容器，无 GitHub 写操作。
- **Idempotency**：`execute()` 对相同输入（相同 `plan`、相同 `workspace_source` 初始内容、`DeterministicPatchReasoner` 的固定映射）产出相同 `ExecutionResult`（`patch`/`changed_files`/`test_outcome` 逐字段相等，`latency` 等价字段不适用——本契约没有单独的延迟字段,由外层 `StepTraceRecord` 承载）；沙箱执行本身允许安全重试（AF-204 §7.1 已确认）。

## Failure Modes

| 场景 | 预期行为 |
|---|---|
| 无法读取 `workspace_source` 初始文件 | `ExecutorNodeError(stage="apply", cause_type=...)` |
| `PatchReasoner.generate_patch` 抛异常 | `ExecutorNodeError(stage="apply", ...)` |
| `SandboxRunner.run` 抛异常（而非返回失败态 `SandboxResult`） | `ExecutorNodeError(stage="sandbox", ...)` |
| 沙箱正常返回但测试失败（`exit_code != 0`） | 不抛异常，`ExecutionResult(status="failed", test_outcome.status="failed")`——业务失败,不是 Executor 自身崩溃 |
| 沙箱 `status="timeout"` | `ExecutionResult(status="failed", test_outcome.status="timeout")` |
| Diff 计算失败（例如编码问题） | `ExecutorNodeError(stage="diff", ...)` |
| Plan 未携带任何 `required_tools` 中的 `sandbox_execute`/`test_execute` 能力 | Executor **不做**能力校验（这是 Policy Gate 已经做过的检查，Executor 信任已通过 Policy Gate 的 Plan，见 Non-Goals） |

## Security Impact

Risk Level L2（沙箱内代码修改与测试执行，自动+审计，风险主要由 AF-204 的沙箱隔离承担）。`19_THREAT_MODEL.md` 的 `Tool Abuse` 通过"Executor 不持有 GitHub 凭据、沙箱网络关闭"双重缓解；`Model Output Injection` 在 M2 阶段不适用（`DeterministicPatchReasoner` 不是真实模型，无注入面）,但契约设计（`generate_patch` 返回结构化 `Mapping[str,str]` 而非可执行代码/Shell 命令）已经为未来真实 Reasoner 接入预留了结构化输出边界。
