# Design Note — AF-202 Implement GitHub MCP read tools

> 状态：**Approved v2 / Implemented for Human Review**。依赖 AF-201（已通过 PR #94 Human Merge 并 verified）。v2 行为以共享契约 §0A 为准。
> 前提文档：`docs/design-notes/M2-SHARED-CONTRACTS.md`（第 5、13 节）。GitHub #21。

## Draft v2 implementation contract

- 复用异步 `httpx` 最小客户端和 AF-201 的 token provider；不引入第二套 GitHub SDK。
- `read_repository_tree()` 返回 `RepositoryTree(entries, truncated)`，不能返回裸 list；分页、文件和 diff 返回值都显式报告截断。
- 新增只读 `find_pull_request_by_head_or_marker()`，供 AF-208 做远端 reconciliation；它不能创建或修改 PR。
- 所有错误映射保持稳定、响应体限长且不得泄露 Authorization header。

## Problem

Executor（AF-205）需要读取仓库文件树/文件内容才能生成 Patch；Context（未来接入真实仓库时）与 Draft PR 幂等检查（AF-208）需要读取 Issue/PR/Diff。目前仓库没有任何调用 GitHub 读 API 的封装。

## Objective

按 Issue #21 AC 与共享契约 v2，实现 `GitHubReadClient` 与五个只读工具（`read_repository_tree`/`read_file_content`/`read_issue`/`read_pull_request_diff`/`find_pull_request_by_head_or_marker`），复用 AF-201 的 `InstallationTokenProvider`。共享契约明确只读工具不写 Audit/Trace/Ledger；调用统计留给 M5 OTel。

## Non-Goals

- 不做任何写操作（Contents/Issues/PR 均只读）。
- 不做 Policy Gate 前置校验（`09_SECURITY_BASELINE.md` L0 "Read docs" = Auto,无需审批)。
- 不写 Idempotency Ledger（读操作无副作用，见 SHARED-CONTRACTS §5.3/§11.4）。
- 不引入向量检索（AF-203 范围）。

## Affected Modules

- 新增 `gateway/github/read_tools.py`（`GitHubReadClient` + 五个只读工具 + Schema + 异常类）。
- 新增 `tests/gateway/github/test_read_tools.py`。
- 修改 `settings.py`、`app.py` 与 `.env.example`：接入可配置 timeout 和应用生命周期内的共享只读客户端。
- 修改 `docs/21_TRACEABILITY_MATRIX.md`。
- 不修改 `gateway/github/auth.py`/`webhook.py`（AF-201 冻结）。

## Proposed Flow

### Schema（`schema_version: Literal[1] = 1`，`extra="forbid"`，与 M1 契约风格一致）

```text
class TreeEntry(BaseModel):
    path: str
    type: Literal["file", "dir"]
    size: int | None

class FileContent(BaseModel):
    path: str
    content: str          # 已解码文本；二进制文件返回 truncated=True 且 content=""
    encoding: Literal["utf-8"]
    size: int
    truncated: bool

class IssueSnapshot(BaseModel):
    number: int
    title: str
    body: str
    state: Literal["open", "closed"]
    labels: list[str]

class DiffFile(BaseModel):
    path: str
    patch: str             # 有界截断
    additions: int
    deletions: int

class PullRequestDiff(BaseModel):
    number: int
    files: list[DiffFile]
    truncated: bool         # files 是否因 max_items 被截断
```

### `GitHubReadClient`（`gateway/github/read_tools.py`）

```text
class GitHubReadClient:
    def __init__(self, token_provider: InstallationTokenProvider, timeout_seconds: float): ...

    async def read_repository_tree(self, owner: str, repo: str, ref: str, path: str | None = None, max_items: int = 200) -> RepositoryTree: ...
    def read_file_content(self, owner: str, repo: str, ref: str, path: str) -> FileContent: ...
    def read_issue(self, owner: str, repo: str, issue_number: int) -> IssueSnapshot: ...
    def read_pull_request_diff(self, owner: str, repo: str, pr_number: int, max_items: int = 200) -> PullRequestDiff: ...
```

内部统一一个私有 `_request(method, url, **kwargs)`，负责：附加 `Authorization: Bearer {token_provider.get_token().token}`、应用 `timeout_seconds`、捕获 HTTP 异常并按下表映射、翻页循环（直到 `max_items` 或无更多数据）。

### 错误映射（SHARED-CONTRACTS §5.3 原样落地）

```text
class GitHubReadToolError(RuntimeError): ...
class GitHubResourceNotFoundError(GitHubReadToolError): ...
class GitHubPermissionDeniedError(GitHubReadToolError): ...
class GitHubRateLimitedError(GitHubReadToolError):
    def __init__(self, retry_after: float): ...
class GitHubUpstreamError(GitHubReadToolError): ...
class GitHubTimeoutError(GitHubReadToolError): ...
class GitHubMalformedResponseError(GitHubReadToolError): ...
```

调用方（Executor 等）只需处理这七个类型,不接触底层 HTTP 客户端的异常类型。

## State Ownership / External Side Effects / Idempotency

- **State Ownership**：无新增持久化状态。
- **External Side Effects**：只读 GitHub API 调用,无副作用。
- **Idempotency**：天然幂等（GET）,不写 Ledger。

## Failure Modes

| 场景 | 预期行为 |
|---|---|
| 目标资源不存在 | `GitHubResourceNotFoundError` |
| 权限不足/App 未安装到目标仓库 | `GitHubPermissionDeniedError` |
| 命中 Rate Limit | `GitHubRateLimitedError(retry_after=...)` |
| GitHub 5xx | `GitHubUpstreamError` |
| 请求超时 | `GitHubTimeoutError` |
| 响应体不是预期 JSON 结构 | `GitHubMalformedResponseError` |
| 结果超过 `max_items` | 正常返回,`truncated=True`,不抛异常 |
| 二进制文件读取 | `FileContent(content="", truncated=True)`,不尝试解码为文本 |

## Security Impact

Risk Level L0（只读）。`19_THREAT_MODEL.md` 的 `Tool Abuse` 通过固定四个工具签名（无任意 API 转发能力）与 `max_items` 上限缓解；错误映射刻意不区分"无权限"与"App 未安装"的具体原因（避免向调用方/最终 Prompt 泄露仓库存在性等信息）。
