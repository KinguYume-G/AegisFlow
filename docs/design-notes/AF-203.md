# Design Note — AF-203 Implement repository knowledge ingestion

> 状态：**Draft v2**，等待人工最终 Review。依赖 AF-202、AF-106（已合并）。Codex 在获得批准前不得实现。v2 行为以共享契约 §0A 为准。
> 前提文档：`docs/design-notes/M2-SHARED-CONTRACTS.md`（第 6、13 节）。GitHub #22。

## Draft v2 implementation contract

- `TextChunk` 保存 `content/start_line/end_line`；`RepositoryChunk` 持久化行范围，保证 `CitedSnippet` 可回溯到精确源行。
- `PgVectorContextRetriever.retrieve(request)` 精确实现 AF-106 已冻结协议；可信 `tenant_id` 与 `RepositoryTarget` 由构造函数注入，不从请求文本推导。
- 疑似凭据的 chunk 必须隔离或跳过并写安全计数/审计；不得脱敏后仍作为精确引用返回。
- 使用官方 `pgvector` 包；确定性 hash embedder 只证明 M2 机制正确性，不声称生产语义检索质量。

## Problem

`ContextAgent`（AF-106）目前只能从本地 Fixture 目录检索；真实仓库知识需要被分块、去重、增量索引进 pgvector,并按租户/仓库隔离,才能供未来真实检索使用。M2 没有真实 Model Provider,无法调用真实 Embedding 模型。

## Objective

按 Issue #22 AC（"增量索引；tenant/repo 隔离；检索基准通过"),实现：

1. `repository_chunks` 表（pgvector 列）与迁移；
2. 确定性分块（`chunking.py`）与确定性 Embedder（`embedder.py`）；
3. 增量索引管道（`ingestion.py`)，未变化 chunk 跳过重新嵌入；
4. `PgVectorContextRetriever`（实现 AF-106 的 `ContextRetriever` 协议,供未来切换使用,本 Issue 不接入 Gate 1B 图)。

## Non-Goals

- 不修改 `packs/delivery/context/{agent,ports,fakes}.py`（AF-106 冻结）。
- 不切换 Gate 1B 图的 Context 节点到真实检索（AF-210 仍用 `LocalFixtureContextRetriever`，见 SHARED-CONTRACTS §6.5）。
- 不做语义排序质量评测（Golden Set/SWE-bench 子集是 `17_EVALUATION_PLAN.md`/M5 范围）。
- 不做语法树/AST 感知分块。
- 不引入真实 Embedding 模型（Model Provider 未确认，M3+ 范围）。

## Proposed Flow

### `RepositoryChunk`（`control_plane/domain/knowledge.py`）

```text
class RepositoryChunk(UUIDPrimaryKeyMixin, CreatedAtMixin, Base):
    __tablename__ = "repository_chunks"
    __table_args__ = (
        UniqueConstraint("tenant_id", "repository", "file_path", "chunk_index",
                          name="uq_repository_chunks_location"),
    )
    tenant_id: Mapped[UUID] = ...      # ForeignKey("tenants.id", ondelete="RESTRICT")
    repository: Mapped[str] = ...      # "owner/repo"
    file_path: Mapped[str] = ...       # POSIX 相对路径
    chunk_index: Mapped[int] = ...
    content_hash: Mapped[str] = ...    # sha256 hex
    content: Mapped[str] = ...         # ≤ 4000 字符
    start_line: Mapped[int] = ...      # 1-based inclusive
    end_line: Mapped[int] = ...        # 1-based inclusive
    embedding: Mapped[Vector] = ...    # pgvector, dim=32（占位维度，见 Limitations）
    updated_at: Mapped[datetime] = ...
```

迁移 `0003_add_knowledge_chunks.py`：`CREATE EXTENSION IF NOT EXISTS vector`（幂等，`IF NOT EXISTS`）后建表；`downgrade()` 删表但**不 DROP EXTENSION**（其他表未来可能复用同一扩展，删除扩展是更危险的操作,不属于本迁移回滚范围）。

### 增量索引（`ingestion.py`）

```text
async def ingest_file(
    session: AsyncSession, *, tenant_id: UUID, repository: str, file_path: str,
    raw_text: str, embedder: Embedder,
) -> IngestionReport:
    chunks = chunk_text(raw_text)
    existing = await load_existing_chunks(session, tenant_id, repository, file_path)
    changed = 0
    skipped = 0
    for index, text in enumerate(chunks):
        content_hash = sha256_hex(text)
        if index in existing and existing[index].content_hash == content_hash:
            skipped += 1
            continue
        embedding = embedder.embed(text)
        await upsert_chunk(session, tenant_id, repository, file_path, index, content_hash, text, embedding)
        changed += 1
    removed = await delete_chunks_beyond(session, tenant_id, repository, file_path, len(chunks))
    return IngestionReport(changed=changed, skipped=skipped, removed=removed)
```

整个函数体在**一个数据库事务**内执行（调用方负责 `session` 的事务边界，或函数内部显式 `async with session.begin():`——由 Codex 实现时按项目既有 `session.py` 的会话管理约定选择,保持与 AF-103 既有代码风格一致)。

### `PgVectorContextRetriever`（`pgvector_retriever.py`）

实现 AF-106 已冻结的 `ContextRetriever.retrieve(request)`；构造函数注入可信 tenant/repository target，查询按这两个边界过滤，结果使用持久化行范围映射为 `CitedSnippet`。本 Issue 不接入图。

## State Ownership / External Side Effects / Idempotency

- **State Ownership**：`repository_chunks` 是新的 Core Domain PostgreSQL 表,`tenant_id` 强制存在（Data Principle "tenant-owned 表带 tenant_id"）。
- **External Side Effects**：无（本 Issue 不调用真实 GitHub/模型 API；`raw_text` 由调用方提供,不在本 Issue 内直接调用 AF-202）。
- **Idempotency**：`ingest_file` 对同一 `(tenant_id, repository, file_path)` 重复调用相同内容时不产生任何写操作（`skipped` 计数验证）；`UniqueConstraint` 是并发安全网。

## Failure Modes

| 场景 | 预期行为 |
|---|---|
| 同一文件重复 ingest,内容未变 | 全部 chunk 走 `skipped` 分支,零写入 |
| 文件内容变短（chunk 数减少） | 多余 `chunk_index` 行被删除 |
| 空文本 ingest | `chunk_text` 返回空列表,函数直接删除该文件已有的全部 chunk（等价于"文件已清空"） |
| 跨租户/跨仓库查询 | `PgVectorContextRetriever` 的过滤条件保证零命中,不抛异常 |
| `embedder.embed("")` | 返回全零向量,不抛 `ZeroDivisionError` |

## Security Impact

Risk Level L1。疑似 Secret chunk 在写库前隔离或跳过并记录安全计数，既不进入数据库也不进入日志；不得修改原文后仍作为精确 Citation。租户与仓库边界由可信注入参数强制过滤。
