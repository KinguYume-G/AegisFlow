# Design Note — AF-110 Build Gate 1A end-to-end test

> 状态：**Draft v4**，等待 Human Review。依赖 AF-104–AF-109 全部 Human Merge。

## Problem and Objective

AF-104–AF-109 的独立契约必须被串成一条可重复、可暂停恢复、可定位失败并产生完整 Trace 的 Gate 1A 进程内链路。固定场景为脱敏的退款审计 CSV 导出需求。

## Non-Goals

不接 Temporal、PostgresSaver、真实 Model Provider、Policy Gate、Executor、Reviewer 或外部系统。`InMemorySaver` 不是 production durable HITL。

## State and Assembly

```text
class AgentState(TypedDict, total=False):
    run_id: UUID
    trace_id: UUID
    request: NormalizedRequest
    clarification: Clarification | None
    context: ContextPackage | None
    plan: Plan | None
```

`thread_id=str(run_id)`；不维护第二套 thread identity。`build_gate1a_graph()` 必须显式接收 Clock、IdGenerator、三个 Reasoner/Retriever、HITL Gateway 和 TraceRecorder，不构造默认 fake。

固定节点顺序：Intake → Clarifier → Context → Planner。Clarifier 信息不足时：

1. `request_clarification(run_id,"clarifier",questions)`；
2. `interrupt()`；
3. 用相同 thread 调用 `Command(resume=answers)`；
4. replay 获得同一个 request_id；
5. submit response；
6. `ClarifierAgent.resolve()` 验证并保存 answers；
7. 继续 Context/Planner。

Clarifier 的“完成”Trace 只在 successful resolve/充分判定后记录，避免 interrupt replay 产生重复逻辑完成记录。

## Safe Resume Contract

`resume_gate1a(compiled_graph, run_id, answers)` 在调用 Command 前读取该 thread 的 checkpoint，并确认存在待恢复 interrupt。不存在、已完成或 run 不匹配时抛 `InvalidResumeThreadError`。

稳定安全不变量：错误 thread 不得恢复原运行，不得产出原运行 Plan，不得改变原 checkpoint。实现时按 `uv.lock` 对照 LangGraph API 适配导入/字段名，但不能改变这些不变量。

## Failure and Observability

- 节点异常包装为 `Gate1ANodeError(node, cause_type)`，不泄露不可信输入或 Secret。
- 每个成功完成节点产生一条 StepTraceRecord；同一运行共享 run_id/trace_id。
- M1 没有真实 workflow/step rows，因此 tenant_id/workflow_id/workflow_version/step_id 可以为空，但字段必须存在。
- InMemoryTraceRecorder 是测试证据，不触发真实 Langfuse。
