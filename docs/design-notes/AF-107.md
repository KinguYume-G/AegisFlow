# Design Note — AF-107 Implement Planner Agent contract

> 状态：**Draft v4**，等待 Human Review。依赖 AF-105、AF-106 Human Merge。

## Problem and Objective

Planner 需要从 NormalizedRequest、resolved Clarification 和 ContextPackage 生成结构稳定、可验证且不伪造成本的 Plan，为后续 Policy Gate 提供输入。

## Non-Goals

不连接模型，不执行计划，不实现 Policy Gate/MCP Registry，不生成真实预算或成本，不产生外部副作用。

## Affected Files

- `contracts/measurement.py`、`contracts/plan.py`
- `planner/{__init__,ports,fakes,agent}.py`
- `tests/packs/delivery/planner/`
- `docs/21_TRACEABILITY_MATRIX.md`

## Design

`Measurement` 使用 finite、非负 Decimal；not_available 时 value/unit 必须为空。`ToolRequirement.tool_name` 的 schema v1 固定为：

```text
repository_read | repository_write | test_execute | sandbox_execute | pull_request_write
```

这是稳定 capability contract，不是临时占位符。AF-406 只能通过映射层或 schema v2 扩展。

`PlanTask` 包含 description 和结构化 required_tools；`Plan` 包含 summary、tasks、risk_level、budget_estimate、reasoner_id。

`DeterministicPlanReasoner` 固定输出四个有序任务：读取证据、实施最小改动、运行测试、准备 Draft PR。安全敏感关键词命中时 risk L3，否则 L1；budget 固定 not_available。无 Context 引用时可以生成计划，但必须在 summary 中明确“repository evidence unavailable”，不得编造 citation。

`PlannerAgent` 显式注入 Reasoner；Clarification 不充分时抛 `InsufficientClarificationError`。

## Failure and Security

- 拒绝未知 tool capability、负数/NaN/Infinity measurement、矛盾 measurement 状态。
- Prompt Injection 样式 context 不得改变固定算法或扩大工具集合。
- Reasoner 异常透传，不返回半成品 Plan。
