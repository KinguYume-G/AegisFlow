# Design Note — AF-105 Implement Clarifier Agent contract

> 状态：**Approved v4**。Project Owner / Human Reviewer 已通过 PR #84 审查设计；依赖 AF-104 已通过 PR #85 Human Merge 并标记为 `status:verified`，AF-105 已进入实施。

## Problem and Objective

Clarifier 必须确定性判断需求是否缺少开工信息，并以结构化 question/answer 契约保存 HITL 回复，避免平行列表错位或恢复后答案丢失。

## Non-Goals

- 不连接真实模型，不实现暂停、通知、持久化或 Temporal。
- 不判断业务方案是否合理，不执行用户提供的文本。

## Affected Files

- `contracts/clarification.py`
- `clarifier/{__init__,ports,fakes,agent}.py`
- `tests/packs/delivery/clarifier/`
- `docs/21_TRACEABILITY_MATRIX.md`

AF-105 不创建 `clarifier/hitl.py`；该文件属于 AF-108。

## Design

`ClarificationQuestion`、`Clarification` 的完整字段和 validator 见共享契约第 5 节。`ClarificationReasoner.identify_gaps()` 返回结构化结果；`ClarifierAgent` 必须显式注入 Reasoner，无默认 fake：

```text
class ClarifierAgent:
    def __init__(self, reasoner: ClarificationReasoner): ...
    def clarify(self, request: NormalizedRequest) -> Clarification: ...
    def resolve(self, clarification: Clarification, answers: dict[str, str]) -> Clarification: ...
```

`DeterministicClarificationReasoner` 严格按共享契约中的五项规则和顺序判断：authorized roles、time range、record limit、output fields/redaction、delivery mode。不存在“由实现选择”的额外规则。

`resolve()` 要求所有被提问 field 都有非空答案；缺失时抛 `IncompleteClarificationAnswersError`，成功时清空 questions、设为 sufficient 并保留全部 answers。它不再次调用 Reasoner。

## Failure and Security

- 拒绝重复 field、矛盾 sufficient/questions/answers 状态、超长 question/answer。
- Reasoner 异常透传；用户文本只作为不可信数据，不具备策略或执行权限。
- 额外 answers 可以保存，但受数量和长度上限约束。
