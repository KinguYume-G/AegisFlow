# Design Note — AF-210 Build Gate 1B end-to-end test

> 状态：**Draft v2**，等待人工最终 Review。依赖 AF-203、AF-204、AF-205、AF-206、AF-207、AF-208、AF-209（均为 Draft，先于本 Issue 批准）。Codex 在获得批准前不得实现，也不得创建 PR。v2 行为以共享契约 §0A 为准。
> 前提文档：`docs/design-notes/M2-SHARED-CONTRACTS.md`（第 4、14、15、16 节）。GitHub #29。

## Draft v2 implementation contract

- webhook accepted 后通过显式 dispatch service 进入 Gate 1B；节点和所有 I/O 均 async，使用 `ainvoke` 与异步 resume。
- 运行时 Unit of Work 明确 Run/Step/Audit 的事务边界；外部 GitHub 写入依赖已提交的幂等 claim，失败可安全 reconciliation。
- 所有 Draft PR 路径必须 interrupt 等待 Human Approval；不得按 Plan 的 L1/L2 绕过。
- 可以抽取共享 node factory 复用 Gate 1A，但必须保持 AF-110 行为并通过完整回归。
- 真实 GitHub 测试由 protected environment 下的手动 Workflow 执行；清理仅关闭匹配 Marker 的 PR并删除匹配分支，不声称删除 PR。

## Problem

AF-201–AF-209 各自独立交付了 Gate 1B 所需的全部组件契约，但从未被真正串成一条可运行的链路；M2 Milestone Exit（"Policy 在 Executor 前执行；沙箱改码和测试；Reviewer 有证据；高风险等待审批；Draft PR 成功；重复 Webhook 不重复建 PR"）要求这条链路在**真实测试仓库**上端到端验证。

## Objective

按 Issue #29 AC，实现异步 `build_gate1b_graph()`、`resume_gate1b()` 与 webhook dispatch service，并在独立私有 Fixture 仓库驱动一次真实 Gate 1B 全链路运行。

## Non-Goals

- 不修改 `build_gate1a_graph()`/`resume_gate1a()` 本身（新增函数，不改写）。
- 不引入 Temporal（等待审批仍是进程内 `interrupt()`，见 SHARED-CONTRACTS §0）。
- 不做 RBAC/多租户验证（单一 Bootstrap Tenant）。
- 不做真实语义质量评测（沿用 AF-203 的范围收敛）。
- 不开始 M3 任何 Issue 的工作。

## Affected Modules

- 修改 `runtime/state.py`：`AgentState` 追加 `policy_decision`/`execution_result`/`review_decision`/`approval_reference` 字段（**只追加，不改动已有字段**）。
- 修改 `runtime/graph.py`：新增 `build_gate1b_graph()`、`resume_gate1b()`、`Gate1BNodeError`（不改写 `build_gate1a_graph`/`resume_gate1a`/`Gate1ANodeError`）。
- 新增 `tests/fixtures/gate1b/`（测试仓库坐标、固定 Plan/Patch fixture、期望的审批/PR 结果）。
- 新增 `tests/e2e/test_gate1b.py`。
- 修改 `docs/21_TRACEABILITY_MATRIX.md`、`docs/02_ARCHITECTURE.md`（`runtime/graph.py` 补一句 Gate 1B 说明）。

## Proposed Flow

### `AgentState` 追加字段

```text
class AgentState(TypedDict, total=False):
    # ... AF-110 既有字段不变 ...
    policy_decision: PolicyDecision | None
    execution_result: ExecutionResult | None
    review_decision: ReviewDecision | None
    write_authorization: WriteAuthorization | None
```

### 图结构（`build_gate1b_graph()`）

```text
planner → policy_gate_node
policy_gate_node → (deny) → END（run.status="failed"）
policy_gate_node → (allow) → executor_node
executor_node → reviewer_node
reviewer_node → (execution failed) → rework_node | END
reviewer_node → (execution passed, approval_status="pending") → approval_wait_node
approval_wait_node → (resume, approved) → draft_pr_node → END
approval_wait_node → (resume, rejected) → END（run.status="failed"）
draft_pr_node → (若 review_decision.outcome=="rework"，来自 execution 失败分支) → executor_node   # Rework 边
```

`policy_gate_node`/`executor_node`/`reviewer_node`/`draft_pr_node` 均镜像 AF-110 既有节点的写法：调用对应 Agent/工具、写 `steps` 行（SHARED-CONTRACTS §4.2）、写 `StepTraceRecord`（Executor/Reviewer）或 `AuditEvent`（Policy Gate、Draft PR 工具）、捕获异常包装为 `Gate1BNodeError(node, cause_type)`。

`approval_wait_node` 镜像 AF-110 `clarification_wait_node`：调用 `ApprovalGateway.request_approval(...)`（写入真实 `approvals` 行，SHARED-CONTRACTS §4.3）、`interrupt({...findings...})`、`Command(resume=...)` 携带人工决定、调用 `ApprovalGateway.submit_decision(...)` 后 `ReviewerAgent.resolve(...)`。

### `build_gate1b_graph()` 签名

```text
def build_gate1b_graph(
    *, clock: Clock, id_generator: IdGenerator,
    clarification_reasoner: ClarificationReasoner, context_retriever: ContextRetriever,
    plan_reasoner: PlanReasoner, hitl_gateway: InMemoryClarificationGateway,
    policy_config: PolicyConfig, execution_scope: ExecutionScope,
    patch_reasoner: PatchReasoner, sandbox_runner: SandboxRunner,
    review_reasoner: ReviewReasoner, approval_gateway: ApprovalGateway,
    github_write_client: GitHubWriteClient, github_read_client: GitHubReadClient,
    idempotency_guard: IdempotencyGuard, trace_recorder: TraceRecorder,
    unit_of_work_factory: Callable[[], AsyncUnitOfWork],
) -> CompiledStateGraph[AgentState, None, AgentState, AgentState]:
```

不含默认参数。所有有 I/O 的节点为 async，并通过 `ainvoke`/异步 resume 驱动。允许抽取共享 node factory 复用 Gate 1A，但 AF-110 行为和回归测试必须保持不变。另新增 `Gate1BDispatcher.dispatch(VerifiedWebhookEvent)`，只有 AF-209 Ledger 返回 `Execute` 才创建/恢复对应 run。

## State Ownership / External Side Effects / Idempotency

- **State Ownership**：`AsyncUnitOfWork` 明确每个节点的 Run/Step/Audit 事务；Ledger claim 必须先提交，再执行 GitHub 外部写入，结果通过 claim token 条件完成。
- **External Side Effects**：真实 Docker 容器执行、真实 GitHub API 调用（读+写）。
- **Idempotency**：完整依赖 AF-209 的 `IdempotencyLedger`；E2E 测试需要验证"重复触发同一 run 不产生第二个 PR"。

## Failure Modes

| 场景 | 预期行为 |
|---|---|
| Policy Gate 拒绝 | `run.status="failed"`，不进入 Executor，Reviewer 不被调用 |
| Executor 测试失败 | Reviewer 判定 `outcome="rework"`，图回到 `executor_node` 重试（**本 Issue 的 Rework 循环需要一个最大重试次数上限**，防止无限循环——固定值,例如 2 次，超过后 `run.status="failed"`，见 Test Plan） |
| 审批被拒绝 | `run.status="failed"`，不创建 PR |
| 审批批准 | 创建 Draft PR，`run.status="completed"` |
| 重复触发同一 `run_id` | 第二次调用在 Policy Gate/Executor 阶段可能重新执行（这两步本身允许重试，SHARED-CONTRACTS §7.1 沙箱允许安全重试），但 Draft PR 创建阶段被 AF-209 Ledger 挡下，不产生第二个 PR |
| 用错误 `thread_id` 尝试恢复 approval_wait | `InvalidResumeThreadError`（镜像 AF-110 `resume_gate1a` 的校验逻辑） |

## Security Impact

Risk Level L3（链路末端触发真实 Draft PR 创建）。这是 Gate 1B 全部安全属性的**集成验证点**——单个 Issue 的隔离测试不能证明"组合在一起后授权检查仍然生效"，本 Issue 的 E2E 测试必须包含至少一个"Policy Gate 拒绝"和一个"审批拒绝"的负向全链路场景，而不只是全部通过的 Happy Path。

## Definition of Done

- [ ] `AgentState` 追加四个新字段，AF-110 既有测试全部仍通过。
- [ ] `build_gate1b_graph()`/`resume_gate1b()` 实现，`build_gate1a_graph`/`resume_gate1a` 不受影响。
- [ ] Happy Path（L1/L2 自动放行到 Draft PR）与至少两条负向全链路（Policy 拒绝、审批拒绝）均有 E2E 测试。
- [ ] Rework 循环有最大重试上限，超限测试覆盖。
- [ ] 重复触发不重复建 PR（Idempotency 集成）有测试。
- [ ] 独立私有 Fixture 仓库上完成一次完整 Happy Path（外部资源阻塞项）。
