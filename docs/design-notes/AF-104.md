# Design Note — AF-104 Implement Intake Agent contract

> 状态：**Draft v4**，等待 Human Review。依赖 AF-103；AF-103 已 `CLOSED / status:verified`。批准前不得实现或调整 AF-104 状态。

## Problem and Objective

DeliveryPack 缺少可验证的 Intake 边界。AF-104 创建框架无关的输入标准化契约，把 PRD、Bug、GitHub Issue 或 Feature Request 转为稳定 `NormalizedRequest`，并生成只依赖规范化内容的幂等键。

## Non-Goals

- 不解析真实 GitHub Webhook，不连接模型、数据库或网络。
- 不实现持久去重、内容质量判断、Clarifier 或 Planner。
- 不在业务方法内部读取系统时间或生成随机 ID。

## Affected Files

- `pyproject.toml`、`uv.lock`：显式声明 `pydantic>=2.13,<3`。
- `src/aegisflow_core/packs/delivery/contracts/{__init__,determinism,normalized_request}.py`
- `src/aegisflow_core/packs/delivery/intake/{__init__,agent}.py`
- `tests/packs/delivery/intake/`
- `docs/21_TRACEABILITY_MATRIX.md`

## Design

共享字段、长度、规范化和 SHA-256 算法以 [`M1-SHARED-CONTRACTS.md`](M1-SHARED-CONTRACTS.md) 第 3–4 节为准。

`determinism.py` 定义 `Clock`、`IdGenerator` 及 System/Fixed/Random/Sequential 实现，供后续 Issue 复用。`IntakeAgent` 只注入它实际使用的 `Clock`：

```text
class IntakeAgent:
    def __init__(self, clock: Clock): ...
    def normalize(source_type, source_ref, title, body) -> NormalizedRequest: ...
```

`received_at` 必须为注入 Clock 返回的 timezone-aware UTC 时间。`IdGenerator` 在 AF-104 定义但不注入 Intake；AF-108/110 才是它的首批消费者。

## Failure and Security

- 不支持的 source type、两个空内容字段、超限字段、naive datetime 或无效 idempotency key 均由 Schema 拒绝。
- body 只作为数据处理，Prompt Injection 样式文本不得被执行或解释。
- 输入上限固定：source_ref 2,048、title 500、body 1,000,000 字符。
