# Test Plan — AF-206 Implement Reviewer Agent contract

> 配套 `docs/design-notes/AF-206.md`。状态：**Draft v2**，等待人工最终 Review。共享契约 §0A 的 v2 测试要求具有优先级。

## Scope

验证 `ReviewDecision` 一致性、`ReviewerAgent.review()`/`resolve()` 固定规则、`InMemoryApprovalGateway`（幂等/run 校验/重复拒绝）、`PostgresApprovalGateway`（真实 `approvals` 表读写，需要 CI PostgreSQL 服务容器）。

## Draft v2 mandatory tests

- `approval_status=pending` 不能携带终态 outcome；approved/rejected 解析后模型重新验证成功。
- 任意可创建 Draft PR 的成功执行都进入 pending approval，不存在 L1/L2 自动 Draft PR 用例。
- async InMemory/Postgres gateway 共享相同 contract tests。
- 并发 request 只有一条 approval；数据库直接尝试 terminal→terminal 或 terminal→pending 更新必须失败。

## 测试先行顺序

1. `ReviewDecision` 一致性 validator。
2. `review()` 三分支。
3. `resolve()` 正常与负向路径。
4. `InMemoryApprovalGateway` 幂等/校验/拒绝。
5. `PostgresApprovalGateway` 集成测试。

## Unit Tests

| 测试 | 断言要点 |
|---|---|
| `test_review_decision_requires_outcome_when_not_pending` | `approval_status!="pending"` 但 `outcome=None` → 构造被拒绝 |
| `test_review_decision_forbids_outcome_while_pending` | `approval_status="pending"` 但 `outcome` 非空 → 构造被拒绝 |
| `test_review_execution_failed_returns_rework_without_approval` | execution failed → `outcome="rework"`, `approval_status="not_required"` |
| `test_review_success_is_pending_for_every_risk_level` | L1/L2/L3 测试通过 → `approval_status="pending"`, `outcome=None` |
| `test_review_all_risk_levels_require_approval_before_draft_pr` | 测试通过 + 任意 `risk_level` → `approval_status="pending"`, `outcome=None` |
| `test_resolve_approved_sets_draft_pr_outcome` | `approval.decision="approved"` → `outcome="draft_pr"` |
| `test_resolve_rejected_sets_rejected_outcome` | `approval.decision="rejected"` → `outcome="rejected"` |
| `test_resolve_unknown_decision_value_raises` | 非法 `decision` 值（构造已绕过 Pydantic Literal 的场景，如反序列化外部输入）→ `InvalidApprovalDecisionError` |
| `test_resolve_on_non_pending_decision_raises_value_error` | `approval_status!="pending"` 调用 `resolve()` → `ValueError` |
| `test_in_memory_approval_gateway_idempotent_for_same_run_and_step` | 同一 `(run_id, step_id)` 调用两次 `request_approval` → 相同 `approval_id`,不新建记录 |
| `test_in_memory_approval_gateway_rejects_run_mismatch` | `submit_decision` 用错误 `run_id` → `ApprovalRunMismatchError` |
| `test_in_memory_approval_gateway_rejects_duplicate_decision` | 对已终态 approval 二次提交 → `DuplicateApprovalDecisionError`,首次决定不被覆盖 |

## Integration Tests（PostgreSQL）

| 场景 | 操作 | 断言要点 |
|---|---|---|
| **真实表写入** | `PostgresApprovalGateway.request_approval` | `approvals` 表出现一行 `decision="pending"`，`tenant_id`/`run_id`/`step_id` 正确 |
| **真实表更新** | `submit_decision(decision="approved", ...)` | 该行原地 `UPDATE`，`decided_by`/`decided_at`/`reason` 正确填充,`created_at` 不变 |
| **幂等 request_approval** | 同一 `(tenant_id, run_id, step_id)` 调用两次 `request_approval` | 数据库只有一行,第二次调用返回同一 `approval_id` |
| **重复决定被拒绝** | 对已 `approved` 的行再次 `submit_decision` | `DuplicateApprovalDecisionError`,数据库行未变 |
| **FK 约束验证** | 用不存在的 `run_id`/`step_id` 调用 `request_approval` | 数据库外键约束报错,被包装为结构化异常（不是裸 `IntegrityError` 泄露给调用方） |

## 模块导入边界测试

`packs/delivery/reviewer/` 不允许导入 `gateway/github/*`；`approval_gateway.py` 允许导入 SQLAlchemy 异步会话相关模块。

## Negative / Security Tests

- `ReviewFinding.message` 内容在写入 `approvals`/日志前不需要额外脱敏（Findings 是 AegisFlow 自己生成的结构化摘要，不是不可信外部输入——与 AF-109 `redact()` 应用于 Prompt 的场景不同,但测试仍需确认 Findings 不会意外包含 Executor 沙箱输出的原始未脱敏内容，因为沙箱 stdout/stderr 本身可能包含仓库代码片段）。
- `PostgresApprovalGateway` 的 SQL 操作全部参数化（无字符串拼接),用含特殊字符的 `reason` 值验证。

## 失败判定

- `review()` 的三分支顺序被打乱（例如风险检查先于失败检查）。
- `resolve()` 对非法状态静默兜底而非抛出异常。
- `PostgresApprovalGateway` 允许重复决定覆盖已有终态。
- Findings 中出现未脱敏的疑似凭据内容。

## Limitations

`PostgresApprovalGateway` 的测试覆盖的是"单进程内对真实表的读写正确性"，不覆盖跨进程/跨重启的审批等待（那需要 Temporal，M3 范围）；本 Issue 的"持久化"仅指审批**事实**持久化，不代表"等待"本身跨进程可恢复。
