# Test Plan — AF-207 Implement deterministic Policy Gate v0

> 配套 `docs/design-notes/AF-207.md`。状态：**Draft v2**，等待人工最终 Review。共享契约 §0A 的 v2 测试要求具有优先级。

## Scope

验证 `PolicyDecision` Schema 一致性、`PolicyGate` 三条固定顺序规则、`PolicyGate` 不依赖任何 LLM/Reasoner。纯内存测试，无外部依赖。

## Draft v2 mandatory tests

- `source_ref` 伪造允许仓库但可信 `RepositoryTarget` 不匹配时必须 deny。
- owner/repo/base_ref/installation_id 任一不匹配均 deny；规范化后完全匹配才继续 capability/risk 检查。
- 不存在 `_extract_repository(request)` 或占位字段测试。

## 测试先行顺序

1. `PolicyDecision` allow/deny 一致性 validator。
2. 三条规则各自独立触发（构造只违反单一规则的 Plan）。
3. 多规则同时违反时的顺序断言。
4. 全部通过路径。
5. 模块边界测试。

## Unit Tests

| 测试 | 断言要点 |
|---|---|
| `test_policy_decision_allow_cannot_carry_violated_rule` | `decision="allow"` 但 `violated_rule` 非空 → 构造被拒绝 |
| `test_policy_decision_deny_requires_violated_rule_and_reasons` | `decision="deny"` 但 `violated_rule=None` 或 `reasons=[]` → 构造被拒绝 |
| `test_policy_gate_denies_wrong_repository` | 仓库不匹配的 Plan/Request → `deny`, `violated_rule="repository_scope"` |
| `test_policy_gate_denies_disallowed_tool_capability` | Plan 请求未启用的 `ToolRequirement.tool_name` → `deny`, `violated_rule="tool_capability_scope"`, `reasons` 列出全部违规能力 |
| `test_policy_gate_denies_risk_above_ceiling` | `plan.risk_level` 高于 `config.max_allowed_risk_level` → `deny`, `violated_rule="risk_ceiling"` |
| `test_policy_gate_allows_within_all_rules` | 仓库匹配、工具能力均启用、风险不超限 → `allow`, `violated_rule=None`, `reasons=[]` |
| `test_policy_gate_reports_first_violated_rule_only` | 构造同时违反 repository 与 risk 规则的输入 → 断言只报告 `repository_scope`（顺序在前的规则），不评估后续规则 |
| `test_policy_gate_risk_ceiling_boundary` | `plan.risk_level` 恰好等于 `max_allowed_risk_level` → `allow`（边界含,非严格小于） |
| `test_policy_gate_config_missing_raises_configuration_error` | 配置缺失 → `ConfigurationError` |

## 模块导入边界测试

`gateway/policy/gate.py` **不允许**导入任何模型/Reasoner/LLM 客户端相关模块（这是本 Issue 的核心安全断言，直接用 AST 扫描或 import-linter 规则验证，而不仅是人工审查）；允许导入 `packs/delivery/contracts/plan.py`、`normalized_request.py`、`policy_decision.py`。

## Negative / Security Tests

- 空 `enabled_tool_capabilities` 配置 → 任何请求任意工具能力的 Plan 都被拒绝（验证"默认拒绝"而非"默认允许"的配置语义）。
- `PolicyGate.evaluate` 签名不接受任何 Prompt/自由文本参数（只接受结构化 `Plan`/`NormalizedRequest`）——防止未来误用把不可信文本传入影响规则判断。

## 建议执行的命令

```bash
uv run --locked python -m pytest tests/gateway/policy/ -v
uv run --locked python -m pytest -v
```

## 失败判定

- 任一规则未在预期场景触发,或触发了错误的 `violated_rule`。
- 多规则同时违反时报告了非"顺序最靠前"的规则。
- `gateway/policy/gate.py` 出现任何 LLM/Reasoner 相关 import。

## 本 Issue 不测试的未来能力

RBAC/身份维度的 Contextual Policy（AF-401–AF-409，M4）；预算/成本维度规则；图集成（AF-210）；AuditEvent 写入本身（由调用方图节点负责，AF-210 测试覆盖）。
