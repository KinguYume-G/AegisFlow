# Test Plan — AF-210 Build Gate 1B end-to-end test

> 配套 `docs/design-notes/AF-210.md`。状态：**Draft v2**，等待人工最终 Review。共享契约 §0A 的 v2 测试要求具有优先级。

## Scope

验证异步 webhook dispatch → Gate 1B、Rework 上限、审批与 Idempotency，并在独立私有 Fixture 仓库完成真实运行。组件测试使用 fake，真实 E2E 使用受保护的手动 Workflow。

## Draft v2 mandatory tests

- `repository_dispatch` webhook 到异步 Gate 1B 的真实 dispatch 路径，不允许只直接调用 graph 绕过入口。
- L1/L2/L3 三种 Plan 在 Draft PR 前均 interrupt；只有绑定正确的 Human Approval 能 resume。
- Unit of Work 在每个故障注入点保持 Run/Step/Audit 与 Ledger 可 reconciliation。
- 同一 delivery 并发/重放最终只有一个 Draft PR；真实测试由 protected environment 手动 Workflow 执行。
- 清理验证 PR 为 closed、Marker 分支被删除；不得断言 GitHub PR 被删除。

## 测试先行顺序

1. `AgentState` 新字段结构测试。
2. `build_gate1b_graph()` 显式注入构造测试。
3. Happy Path（fake 组件）。
4. 负向路径：Policy 拒绝、审批拒绝、Rework 超限。
5. Idempotency 集成（重复触发）。
6. 真实测试仓库集成（阻塞项）。

## Unit / Component Tests（fake 组件，不需要真实 Docker/GitHub）

| 测试 | 断言要点 |
|---|---|
| `test_agent_state_accepts_new_gate1b_fields` | `AgentState` 可携带 `policy_decision`/`execution_result`/`review_decision`/`approval_reference` |
| `test_build_gate1b_graph_requires_all_dependencies` | 遗漏任一必需参数 → 构造错误 |
| `test_build_gate1a_graph_unaffected_by_gate1b_additions` | 回归：AF-110 既有测试套件在本 Issue 合并后原样通过 |

## Integration Tests（E2E，fake 组件驱动全链路）

| 场景 | 操作 | 断言要点 |
|---|---|---|
| **Happy Path（所有风险等级）** | 固定 Fixture 驱动，分别使用 L1/L2/L3 Plan | Policy allow → Executor 完成 → Reviewer pending → Human Approval resume → Draft PR 创建 → `run.status="completed"` |
| **Policy 拒绝** | Fixture 构造越权工具能力的 Plan | `policy_decision.decision="deny"` → 图终止于 `failed`，Executor/Reviewer 均未被调用（断言 mock 未被调用,而不只是断言最终状态） |
| **高风险审批批准** | Plan 风险为 `L3`，`Command(resume=...)` 提交 `approved` | Reviewer 触发 `interrupt()` → 恢复后 `outcome="draft_pr"` → Draft PR 创建 |
| **高风险审批拒绝** | 同上，`Command(resume=...)` 提交 `rejected` | 恢复后 `outcome="rejected"`，`run.status="failed"`，未创建 PR |
| **Rework 循环与上限** | Executor 首次测试失败 → Reviewer `outcome="rework"` → 图回到 Executor;fixture 设定连续失败超过上限 | 达到最大重试次数后 `run.status="failed"`，不无限循环（用超时/步数上限双重保护断言,防止测试本身挂起） |
| **重复触发不重复建 PR** | 用相同 `run_id` 完整跑两次 Happy Path | 第二次调用中 `IdempotencyGuard.check()` 命中,mock GitHub 写客户端在第二次运行中**零调用** |
| **错误 thread 恢复被拒绝** | 用不匹配的 `run_id` 调用 `resume_gate1b` | `InvalidResumeThreadError` |
| **Trace/Audit 完整性** | 检查 `InMemoryTraceRecorder` 与测试数据库中的 `audit_events`/`steps`/`approvals` | Policy Gate/Draft PR 写 `AuditEvent`；Executor/Reviewer 写 `StepTraceRecord`（`agent="executor"`/`"reviewer"`）；每个节点对应一行 `steps`；高风险场景下 `approvals` 有对应行 |

## 真实测试仓库集成测试（需要 Fixture/App，标记 `@pytest.mark.real_github`，不在默认 CI 中自动运行）

| 场景 | 操作 | 断言要点 |
|---|---|---|
| **端到端 Happy Path** | 对真实测试仓库触发一次完整 Gate 1B 运行 | 真实 Draft PR 被创建，包含正确 Marker，分支命名符合约定 |
| **清理** | 运行结束后 | 测试创建的分支/PR 被自动清理（或标记待清理，视最终清理机制而定） |

## 模块导入边界测试

`runtime/graph.py` 允许导入本 Bundle 全部 Agent/Gateway 模块；`packs/delivery/*` 各 Agent 目录之间不允许互相导入（沿用 M1 规则）。

## Negative / Security Tests

- Policy 拒绝场景下,断言 Executor 的 `SandboxRunner`/GitHub 写客户端**零调用**（不只是断言最终状态正确,防止"结果碰巧正确但中途仍然执行了不该执行的副作用"这类隐蔽 Bug）。
- 审批拒绝场景下,断言未创建任何 GitHub 资源。
- Rework 循环上限测试必须真正验证"不会无限循环"，而不是假设理论上限生效（用 `pytest-timeout` 或等价机制包裹测试本身,防止设计缺陷导致 CI 无限挂起）。

## 建议执行的命令

```bash
uv run --locked python -m pytest tests/e2e/test_gate1b.py -v -m "not real_github"
uv run --locked python -m pytest tests/e2e/test_gate1b.py -v -m real_github   # 需要真实测试仓库与 GitHub App 凭据
uv run --locked python -m pytest -v   # 完整回归，含 AF-101–AF-209 全部既有测试
```

## 预期结果

- Happy Path、两条负向路径、Rework 上限、重复触发保护均通过。
- 真实测试仓库上产出一个真实 Draft PR，PR 描述/Evidence 附链接。
- 完整 `pytest` 套件保持通过。

## 失败判定

- 任一负向路径未能在预期节点终止，或终止后仍产生了副作用。
- Rework 循环无上限或上限测试本身挂起。
- 重复触发产生第二个 PR。
- 真实测试仓库运行未被验证（Definition of Done 中标记为阻塞项，不能用 mock 结果替代）。

## 本 Issue 不测试的未来能力

Temporal Worker Kill 恢复（M3，Gate 2）；跨租户隔离（M4）；真实语义检索质量（M5）；k3s 部署（M5）。
