# Test Plan — AF-204 Implement local Docker sandbox baseline

> 配套 `docs/design-notes/AF-204.md`。状态：**Draft v2**，等待人工最终 Review。共享契约 §0A 的 v2 测试要求具有优先级。

## Scope

验证 `SandboxRunner`、确定性 InMemory fake、真实 Sandbox Broker adapter、服务端参数授权边界与清理保证。

## Draft v2 mandatory tests

- Broker 拒绝 privileged、device、socket mount、workspace 外 bind mount、额外 capability、network 和未锁 digest 镜像。
- 只能 wait/log/stop/remove 由当前 broker 创建且 Marker 匹配的容器。
- runner 返回时 workspace 仍存在；容器在成功、超时和异常路径都清理，workspace 由调用方稍后清理。
- InMemory fake 在所有测试中都不创建宿主子进程。

## 测试先行顺序

1. `SandboxRequest`/`SandboxResult` Schema 边界测试。
2. `InMemorySandboxRunner` 正常路径（不需要 Docker）。
3. `DockerSandboxRunner` 安全属性逐项测试（需要真实 Docker）。
4. 超时/资源超限/清理测试。
5. Sandbox Broker 参数校验与逃逸负向测试。

## Unit / Component Tests（不需要真实 Docker）

| 测试 | 断言要点 |
|---|---|
| `test_sandbox_request_rejects_empty_command` | `command=[]` → Pydantic 校验错误 |
| `test_sandbox_result_truncates_long_output` | 超过 64KB 的 stdout/stderr 被截断并追加 `[TRUNCATED]` |
| `test_in_memory_sandbox_runner_executes_command` | 简单命令（如 `echo`）→ `status="completed"`, `exit_code=0` |
| `test_in_memory_sandbox_runner_captures_nonzero_exit` | 失败命令 → `status="completed"`, `exit_code!=0`（区分"执行完成但命令失败"与"沙箱自身失败"） |
| `test_in_memory_sandbox_runner_cleans_up_temp_dir` | 执行后临时目录被删除（无论命令成功失败） |

## Integration Tests（需要真实 Docker，标记 `@pytest.mark.docker`，CI 环境已有 Docker daemon）

| 场景 | 操作 | 断言要点 |
|---|---|---|
| **non-root 验证** | 沙箱内执行 `id -u` | 输出非 `0` |
| **read-only FS 验证** | 沙箱内尝试写入 `/etc/test`（非 `/workspace`/`/tmp`） | 写入失败（只读文件系统错误），`exit_code != 0` |
| **no Docker socket 验证** | 沙箱内检查 `/var/run/docker.sock` 是否存在 | 不存在 |
| **network=none 验证** | 沙箱内尝试连接一个已知可达的外部地址（如 DNS 解析或 TCP 连接） | 连接失败/超时,证明网络确实关闭 |
| **resource limit 验证** | `memory_limit_mb` 设置一个很小的值,运行一个尝试分配超量内存的脚本 | `status="resource_exceeded"` 或进程被 OOM Kill,不是无限挂起 |
| **timeout 验证** | `timeout_seconds` 设为 2,命令为 `sleep 30` | `status="timeout"`,总耗时接近 2 秒而非 30 秒,容器已被清理（后续 `docker ps` 不再出现该容器 ID） |
| **workspace 修改可见性** | 沙箱内修改 `/workspace` 下的文件 | `workspace_output` 目录反映修改后的内容,供调用方 diff |
| **所有权分离** | mock 容器 remove 失败 | runner 报结构化清理错误且 workspace 仍存在；调用方仍能在独立 finally 清理 workspace |

## Sandbox Broker 安全测试

| 测试 | 断言要点 |
|---|---|
| `test_broker_does_not_expose_docker_api` | 对 Broker 请求原生 Docker API 路径 | 404/拒绝，证明只暴露 AegisFlow 协议 |
| `test_broker_rejects_unpinned_image_and_unsafe_parameters` | 请求未锁镜像、privileged、devices、socket/host mount、network 或额外 capability | 全部在创建容器前拒绝 |
| `test_broker_only_manages_owned_marked_containers` | 尝试操作 Marker 不匹配的容器 | 拒绝且目标容器不变 |

## 模块导入边界测试

`gateway/sandbox/` 允许导入 Docker SDK；`packs/delivery/*` 不允许直接导入 Docker SDK,只能通过 `SandboxRunner` 协议调用。

## Negative / Security Tests

- 沙箱内环境变量不包含任何 GitHub/Langfuse/数据库凭据（`docker inspect` 或容器内 `env` 命令输出断言）。
- `workspace_source` 路径穿越（例如指向 `/etc` 等系统目录）时被拒绝,不允许把任意宿主路径作为工作区源（复用 AF-106 的 root 校验思路）。
- 并发调用 `run()`（多个沙箱同时执行）不互相干扰、不共享临时目录。

## 建议执行的命令

```bash
uv run --locked python -m pytest tests/gateway/sandbox/ -v -m "not docker"
uv run --locked python -m pytest tests/gateway/sandbox/ -v -m docker   # 需要本地/CI Docker daemon
uv run --locked python -m pytest -v
docker compose build core sandbox-broker
```

## 失败判定

- non-root/read-only/no-socket/network=none 任一属性未生效——阻塞级安全失败。
- 超时后容器未被清理（残留容器）。
- Broker 接受任何未经允许的镜像、mount、capability、network 或容器标识——阻塞级安全失败。
- 沙箱内可访问任何凭据或宿主敏感路径。
